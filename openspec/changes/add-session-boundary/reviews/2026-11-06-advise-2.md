## Independent take — recorded before comparison

1. Pin a core import graph free of Node builtins and driver packages, including lazy association and collection paths.
2. Pin a core-only model binding API that carries an explicit scope into every database operation.
3. Pin captured model, builder, instance, hook, and association scope ahead of any later Node ambient binding.
4. Refuse an association implementation that delegates to an unbound related class and silently loses its owner's scope.
5. Keep Node defaults and AsyncLocalStorage in the Node entry; core may resolve an injected provider but must own no default session.
6. Pin transaction callbacks to the driver's transaction session, retaining the same child scope across awaited work.
7. Refuse nested transactions through either the callback scope or its retained root, while allowing independent roots to transact.
8. Pin retirement on every transaction completion path and reject escaped child work before touching the driver.
9. Pin child-close versus root-close ownership, including rollback ordering when the root closes during a callback.
10. Accept the tradeoff of explicit core binding and a narrower shared PgDatabase surface to gain portability without redesigning the integration harness.

## Comparison with the revised contract

The three revisions requested by `reviews/2026-11-06-advise.md` are answered at the architecture level. This accepts the proposed contract for implementation; it does not certify completed code or tests.

1. **R1 — core binding and precedence: answered.** `design.md:17` supplies `scope.model(table)` as the core-only binding path and defines `run` as passing the scope without retargeting an already bound model. The delta's Explicit scope, Captured scope wins, and Node ambient binding requirements (`specs/session-boundary/spec.md:21`, `:42`, `:70`) pin explicit capture ahead of both AsyncLocalStorage and the Node default. Hooks and related loads inherit the owner's scope, including the transaction child. This directly addresses the unbound `RelatedModel.find` delegation at `src/associations.ts:78`. The Node-installed reader leaves the default session in the Node entry and specifies context restoration. The API expression and surrounding behavioral requirements are concrete enough to implement without requiring a separate example document.
2. **R2 — nested-transaction receiver: answered.** The Nested transaction requirement (`specs/session-boundary/spec.md:92`) explicitly rejects both callback-scope re-entry and re-entry on its retained root while that transaction is open, permits a different root to transact concurrently, and forbids flattening and savepoints. `design.md:27` and `tasks.md:6` reflect that choice. Root identity is the chosen coordination boundary: the contract deliberately rejects concurrent transaction entry on the same root, even if the underlying pool could provide another connection. No ambient ancestry inference or process-wide queue is needed.
3. **R3 — lifetime and ownership: answered.** Explicit scope and Transaction scope lifetime (`specs/session-boundary/spec.md:21`, `:111`) require the child to use the driver's transaction session; retire its token on commit, rollback, and completion errors; reject escaped child/builders before driver I/O; and distinguish child close from root close. Root close during active work has a concrete rollback, retirement, and owned-client-close order. The callback and awaited hooks must finish before commit. These are observable lifecycle decisions, with internal token representation left to implementation.

The rest of the blind take is also covered: `design.md:41` inventories the eager loader and both collection proxies, and `design.md:58` plus `tasks.md:11` require checks through published subpaths and dynamic imports. That matters because `src/collection-proxy.ts:210` currently imports the connection module lazily. The shared session surface and adapter/harness deferrals remain consistent with the stated seam change.

## Steelman against the independent take

My strongest concern was that a retained-root prohibition would serialize a pooled adapter unnecessarily. The revised contract makes that restriction explicit per root and allows independent roots; that is a defensible portable ownership rule, not a reason to demand a more complex context-sensitive design. Likewise, a Node-owned default may resemble the previous global fallback, but it is an intentional compatibility path for unbound Node calls. Explicit captures bypass it, and core-only usage requires no Node installation. Removing the compatibility default would exceed the proposed work.

Root close during an active callback is more demanding than simply rejecting close. However, the author has now chosen a clear outcome and carried it into the lifecycle test obligation. A different close policy is not required to satisfy this review. The mechanism must be proved during implementation; this review does not claim driver cancellation has already been validated.
