## Independent take — written before reading the design, tasks, delta, or reviews

1. Pin the proven native host / WASI Postgres boundary, one owner thread and Store, with no Node dependency in the server path.
2. Pin the guest, Wasmtime version, seed cluster, and supported host platform; refuse to turn a draft-artifact spike into a general production claim.
3. Pin a finite caller pool and queue, explicit overload behavior, and statement serialization; refuse any second entry into the Store.
4. Pin transaction ownership across waits, holder progress ahead of unrelated waiters, nested-transaction rejection, and irreversible token retirement.
5. Pin deadlines and interruption behavior for both queued callers and a stuck guest; refuse cleanup that depends on the stuck execution yielding voluntarily.
6. Pin SQL text plus separately bound values, result/error encoding, and a minimum type contract; refuse interpolation as evidence of parameter safety.
7. Pin one private preopen, exclusive directory ownership, safe first initialization, and a separate-process reopen check; refuse overwriting an existing cluster.
8. Pin session-state isolation, rejection of unauthorized transaction controls, and recovery after SQL errors; refuse state leakage between callers.
9. Pin shutdown and fatal-failure outcomes, including uncertain commits and pending callers; refuse automatic replay when execution might already have happened.
10. Tradeoff: a small experimental native SQL service can ship before a full ORM bridge, provided its runnable caller boundary and limits are explicit and existing JS scopes remain intact.

## Comparison and steelman

The current contract answers the host ownership, admission, parameter boundary, directory, and recovery concerns. `design.md:3–7,23` pins the demonstrated artifact/runtime and arm64 macOS scope. The delta's Native Wasmtime host requirement names the in-process operations and separate parameters. One owner queue bounds parked callers to eight, rejects overflow immediately without a hidden wait, serializes holder bypass, and limits the holder backlog to one (`specs/wasmtime-process/spec.md:51–78`). Token retirement prevents stale-token dispatch and requires an idle session before a successor enters; failed cleanup closes this process to subsequent work (`:80–94`). Seeded directory and one owner rejects empty storage and a second host without reseeding or taking over a present lock (`:34–49`). The acceptance command in `tasks.md:6` makes the required behavior concrete.

The strongest case against making every line of my independent take a blocker is the deliberately narrow native facility. Its callers are in-process, its operations return rows or errors, and it does not claim an ORM bridge, a network service, a general SQL type system, or production hardening. I do not require the neighboring JavaScript callback-scope lifecycle or PGlite session-state restrictions to be copied into this separate capability. Session-state sanitization, comprehensive shutdown/retry semantics, and a richer value contract are beyond the claims being accepted here. The existing living specs remain authoritative for their own adapters.

In particular, my initial preference for guest interruption is stronger than this milestone needs. `design.md:9` and the queue delta explicitly bound waiting only. Expiry removes the waiter and must not abort another caller's transaction. A stalled guest or holder can therefore retain ownership indefinitely, but new parked requests still have a finite wait and admission is bounded. This is an explicit limitation, not evidence of execution deadlines or automatic recovery. The PGlite adapter's different timeout-driven rollback requirement is untouched. Likewise, process reopen evidence does not establish power-loss safety, Linux support, or repair of the draft guest's stubs. Fault injection is sufficient for the host's specified failed-cleanup response.

## Resolution of the previous send-back

**R5 is resolved.** `tasks.md:5` now requires removal of the expired waiter, a timeout error, no dispatch, and preservation of the holder's transaction. This agrees with `design.md:9`, the delta at `specs/wasmtime-process/spec.md:52,72–78`, and the acceptance command's coverage. The task no longer directs an executor to roll the holder back.

**R6 is resolved.** `design.md:13` and the delta at `specs/wasmtime-process/spec.md:4` agree on case-insensitive rejection of `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `START`, `END`, and `ABORT` after removing leading whitespace and comments. They explicitly reject a semicolon followed by non-whitespace and allow a single trailing semicolon. The rejection occurs before guest dispatch and preserves transaction/token state. The scenario at `:12–17` and `tasks.md:6` cover `END`, comment-prefixed `START TRANSACTION`, and multiple statements. This answers the prior request for an explicit restricted surface; it is not a claim to parse general SQL. The deliberately conservative semicolon rule may reject otherwise valid SQL text containing semicolons, which is acceptable for this bound-parameter milestone.

The earlier R1–R4 decisions remain present and their checkboxes remain checked. No further owed item is required for this contract. Acceptance approves the specified work for implementation; it does not certify an implemented host or a passing acceptance run.
